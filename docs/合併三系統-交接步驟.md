三個系統目前是**三個獨立的 Supabase 專案**（品質／後勤／缺陷）。目標是把後勤與缺陷併入品質專案。

## 2. 你要做的事（約 5 分鐘）

### 步驟 A：在品質專案執行 SQL
1. 打開 Supabase，進入**品質系統**的專案（不是後勤、不是缺陷）。
2. 左邊 **SQL Editor** → **New query**。
3. 貼上 `supabase/merge-boh-defect.sql` 全部內容（檔案在這個 repo；也可用網址複製：
   `https://raw.githubusercontent.com/Build-0/hqms/master/supabase/merge-boh-defect.sql`）。
4. 按 **Run**。看到 **Success** 即完成。可以重複執行，不會重複建表。

這份 SQL 做了什麼：
- 建立後勤資料表（`categories` 改名 `boh_categories`，避免與品質系統撞名）與全部後勤函式；
- 建立缺陷資料表（`defect_users`、`defect_records`、`defect_types`）與 `defect-photos` 相片桶；
- 全部設為**開放模式**（匿名可讀寫），之後再統一收緊權限；
- 後勤的「管理密碼」改為永遠通過（開放模式）。

### 步驟 B：叫 Claude 接手搬資料
把這份文件交給 Claude（在公司電腦開同一個 repo），說「SQL 已執行，請繼續搬資料」。Claude 會：

1. `git pull` 拿最新程式；
2. 確認本機 `.env` 有品質專案的 `VITE_SUPABASE_URL` 與 `VITE_SUPABASE_ANON_KEY`（沒有的話要你補；這兩個值在 Supabase → Project Settings → API）；
3. 執行 `node scripts/merge-copy.mjs`：複製後勤約 1,000 筆（含相片，約 37 MB）與缺陷 341 筆，並把 353 張缺陷相片搬到新專案的 `defect-photos`；
4. 腳本最後會逐表核對筆數，全部顯示 ✓ 才算成功；
5. 再執行 `node scripts/merge-patch.mjs`：把嵌入頁面改連品質專案，並把 `categories` 改成 `boh_categories`、缺陷的表改名；
6. build、commit、push，部署後用手機測試後勤與缺陷資料是否都見到、相片是否正常。

## 3. 搬完之後

- **先不要刪舊專案。** 觀察 1–2 星期，確認後勤與缺陷的資料、相片、編輯、匯出都正常。
- 刪除前先在舊專案做備份下載。
- 刪除舊專案的位置：Supabase → 該專案 → Project Settings → General → Delete project。**刪除不能復原。**
- 舊缺陷網站（`rooms-defelt.netlify.app`）仍連舊缺陷專案，搬完後它與新版會是兩份各自獨立的資料，請只使用新版，避免資料分岔。

## 4. 已知問題與注意事項

1. **缺陷系統密碼安全**：缺陷的 `users` 表密碼是**明文**，且任何人憑公開金鑰都讀得到。目前按你的決定維持開放，之後要改成 Supabase 登入（密碼加密）。你曾在對話貼出管理員密碼，建議之後更改。
2. **後勤管理密碼**：原 `supabase/` 的 SQL 內曾有明文初始密碼（舊 repo `Build-0/boh` 仍可見），合併後的後勤已改為開放模式，但舊 repo 的歷史仍在。
3. **品質系統為開放模式**：任何知道網址的人都可讀寫全部資料（包含房務員資料與評分）。
4. 嵌入的後勤／缺陷頁面各自保留原本的內部樣式，只統一了主色與標題列。
5. 缺陷匯出報告在使用真實資料時，需要先登入缺陷系統才能匯出。

## 5. 之後可做的功能

1. 查房「轉為缺陷」：從查房記錄一鍵建立缺陷，處理完成後在查房記錄顯示結果（要先完成併庫）。
2. 統一登入與角色權限（含收緊開放模式）。
3. 把嵌入的後勤、缺陷逐步改寫成原生模組，樣式與品質系統完全一致。
